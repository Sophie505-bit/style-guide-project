# Коммиты

Сообщения коммитов оформляются по соглашению
[Conventional Commits](https://www.conventionalcommits.org/ru/).

## Формат

```text
<тип>(<область>): <описание>

[необязательное тело]

[необязательные футеры]
```

- **Тип** — из таблицы ниже, обязателен.
- **Область** — раздел руководства или документации: `tone`, `structure`,
  `ci`, `readme`. Рекомендуется, но не обязательна.
- **Описание** — с маленькой буквы, в императиве, без точки в конце,
  до 72 символов.
- **Тело** — зачем сделано изменение, если это неочевидно. Через пустую
  строку после заголовка.
- **Футеры** — ссылки на задачи: `Closes #42`.

## Типы коммитов

| Тип | Когда использовать |
| --- | --- |
| `docs` | Изменения документации — основной тип в этом репозитории |
| `feat` | Новая функциональность сайта документации |
| `fix` | Исправление: опечатка, битая ссылка, неверный факт |
| `style` | Оформление без изменения смысла |
| `refactor` | Перестройка структуры без изменения содержания |
| `ci` | Изменения CI/CD и линтинга |
| `chore` | Обслуживание: зависимости, конфигурация |

## Примеры

Хорошо:

```text
docs(accessibility): добавить раздел о доступности текста
docs(tone): запретить канцелярит в примерах
fix(links): исправить битую ссылку на глоссарий
ci: добавить проверку орфографии в workflow
docs: обновить инструкцию по локальной сборке

Closes #42
```

Плохо и почему:

| Сообщение | Проблема |
| --- | --- |
| `update` | Непонятно, что и зачем изменено |
| `Добавил раздел.` | Русский язык, точка в конце, прошедшее время |
| `fix bug` | Infix-тип без области и сути: какой баг? |
| `docs: Добавить раздел про доступность!!!` | Прописная буква, лишние знаки |
| `WIP` | Промежуточные коммиты перед merge объединяются (squash) |

## Область применения

- В репозитории руководства используется только `docs`, `fix`, `ci`, `chore`.
- Промежуточные коммиты вида «небольшая правка» допускаются в личной ветке,
  но при слиянии Pull Request выполняется squash — в `main` попадает один
  аккуратный коммит. **SHOULD**

## Автоматическая проверка

Сообщение коммита в `main` должно соответствовать шаблону
`^(docs|feat|fix|style|refactor|ci|chore)(\(.+\))?!?: .+`.
Нарушение — основание вернуть PR на доработку. Проверка выполняется
на ревью; опционально подключается commitlint в CI.

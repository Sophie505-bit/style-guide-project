# Терминология

## Один термин — одно понятие

В пределах всего руководства и всей документации организации одно понятие
обозначается одним термином. Синонимы в справочных текстах запрещены:
читатель не может знать, что «аккаунт» и «учётная запись» — одно и то же. **MUST**

Зафиксированные термины (полный список — в [глоссарии](../glossary.md)):

| Используем | Не используем |
| --- | --- |
| учётная запись | аккаунт, профиль |
| приложение | аппликация, апп |
| репозиторий | репа, проект (в значении репозитория) |
| веб-интерфейс | web UI, морда |
| удалить | снести, убрать, почистить |

## Новые термины

1. Термин вводится при первом употреблении: расшифровка и, при необходимости,
   английский оригинал в скобках: «пул-реквест (pull request)».
2. Перед вводом нового термина проверьте [глоссарий](../glossary.md) —
   возможно, термин уже есть.
3. Новый устойчивый термин добавляется в глоссарий той же задачей,
   что и документ, где он появился. **SHOULD**

## Заимствования и латиница

- Устоявшиеся заимствования пишутся по-русски: «сервер», «коммит», «релиз»,
  «деплой», «бэкенд» (**SHOULD**).
- Технические имена не переводятся и не склоняются латиницей: «откройте
  GitHub», а не «зайдите в GH». Склонение латиницы («в GitHub’е») запрещено —
  перефразируйте. **SHOULD**
- Написание продуктов — по официальному стилю вендора: «GitHub», «Python»,
  «PostgreSQL», «MySQL», «JavaScript», «macOS». **MUST**

## Аббревиатуры

- Аббревиатура вводится при первом употреблении: «непрерывная доставка
  (CI/CD)», далее — «CI/CD». **SHOULD**
- Общеизвестные аббревиатуры (API, URL, JSON, HTTP) расшифровки не требуют.
- Аббревиатуры не дублируются словом: «API-интерфейс» → «API». **SHOULD**

## Регистр

- Названия элементов интерфейса — как в интерфейсе: кнопка **Сохранить**. **MUST**
- Названия технологий — по бренду: «TypeScript», а не «typescript» (в тексте).
- Русские названия разделов и заголовки — только первое слово с прописной:
  «Настройка интеграции», а не «Настройка Интеграции». **SHOULD**

# Именование файлов, папок и репозиториев

## Общие правила

- Только строчные латинские буквы, цифры и дефис: `kebab-case`. **MUST**
- Пробелы, подчёркивания, `CamelCase` и транслит в именах запрещены:
  `Как_настроить.md` и `kak-nastroit.md` недопустимы. **MUST**
- Имя описывает содержимое: `deploy-howto.md`, а не `doc1.md`. **MUST**
- Версии и даты в именах файлов запрещены: `guide-v2-final.md`.
  Версия хранится в git, а не в имени. **MUST**

## Документация

- Имя файла — от заголовка страницы в падеже, удобном для чтения:
  заголовок «Голос и тон» → `tone.md` или `voice-and-tone.md`.
- Индексная страница раздела — `index.md`; README репозитория — `README.md`. **MUST**
- Папки разделов документации: `text/`, `formatting/`, `documents/`,
  `process/` — по крупным темам, не глубже двух уровней вложенности. **SHOULD**
- Изображения: `docs/<раздел>/images/название.svg`, имя латиницей. **MUST**
- Файлы вложений и примеров: `examples/config-example.yaml`. **SHOULD**

## Репозитории и ветки

| Объект | Правило | Пример |
| --- | --- | --- |
| Репозиторий | `kebab-case`, по назначению | `style-guide-project` |
| Ветка | `тип/краткое-описание` | `docs/accessibility-section` |
| Тип ветки | `feature`, `fix`, `docs`, `chore`, `hotfix` | `fix/broken-links` |

- Ветки `test`, `my-branch`, `1`, `temp` запрещены: по имени должно быть
  понятно назначение. **MUST**
- Ветка живёт до merge в `main` и удаляется после. **SHOULD**

## Версии и даты в названиях

Единственное исключение — релизные артефакты и теги:

- тег релиза: `v2.4.0` (**MUST**);
- файлы дистрибутива: `reporter-2.4.0.tar.gz` — версия внутри имени продукта
  допустима;
- дата в имени файла допустима только для протоколов и выгрузок:
  `2026-10-12-retro.md`. **MAY**

## Проверка

- Линтер проверяет имена только в ссылках (битые ссылки ломают сборку).
  Остальное — зона ревьюера.
- При переименовании файла обновите все ссылки на него в репозитории
  и в `mkdocs.yml` — это часть одного Pull Request. **MUST**

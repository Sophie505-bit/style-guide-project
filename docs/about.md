# О руководстве

## Область применения

Руководство распространяется на всю документацию по разработке ПО
в организации:

- файлы документации в репозиториях: `README.md`, `CONTRIBUTING.md`,
  `CHANGELOG.md`, ADR, комментарии в коде;
- инструкции и руководства пользователя;
- справочники API и описания интеграций;
- статьи внутренней вики и базы знаний.

Руководство **не** регламентирует: маркетинговые материалы, тексты интерфейса
(UI-copy), юридические документы — для них действуют отдельные стандарты.

## Кому адресовано

Всем сотрудникам, которые создают или изменяют документацию: разработчикам,
аналитикам, тестировщикам, техписателям и менеджерам. Отдельных «людей,
которые пишут документацию» нет — правило «кто меняет код, тот обновляет
документацию» действует по умолчанию.

## Как проверяются правила

| Способ | Что покрывает | Когда срабатывает |
| --- | --- | --- |
| Линтер markdownlint | Оформление: заголовки, списки, таблицы, ссылки | CI, на каждом PR |
| Линтер cspell | Орфография и терминология | CI, на каждом PR |
| Сборка MkDocs `--strict` | Работоспособность ссылок и навигации | CI, на каждом PR |
| Ревьюер | Смысл, тон, полнота, техническая точность | Ревью PR |

Автоматические проверки (markdownlint, cspell, `mkdocs build --strict`)
запускаются в CI на каждом Pull Request: состав проверок описан в
[CONTRIBUTING.md](https://github.com/Sophie505-bit/style-guide-project/blob/main/CONTRIBUTING.md)
и в разделе [Ветки и Pull Request](process/branches-pr.md); процесс ревью —
на странице [Ревью документации](process/review.md).

## Версионирование руководства

Руководство живёт по принципам docs-as-code: хранится в git, меняется через
Pull Request, публикуется автоматически.

- История изменений — в [CHANGELOG.md](https://github.com/Sophie505-bit/style-guide-project/blob/main/CHANGELOG.md).
- Обсуждение спорного правила — issue в репозитории руководства.
- Если правило мешает, его нельзя молча игнорировать: создайте issue
  с описанием проблемы и предложением.

## Роли

| Роль | Ответственность |
| --- | --- |
| Автор | Пишет документ, проходит чек-лист, оформляет PR |
| Ревьюер | Проверяет соответствие руководству и точность фактов |
| Владелец раздела | Принимает изменения в своём разделе, отвечает на вопросы |
| Дежурный по документации | Раз в спринт проверяет «гниющие» ссылки и устаревшие страницы |
